# Чек на удачу

Веб-приложение для регистрации чеков в промо-акции и их проверки модератором.

## Запуск проекта

Нужны Docker и Docker Compose.

1. Склонируйте репозиторий и перейдите в его каталог.
2. Создайте файл `.env` на основе примера:

   ```bash
   cp .env.example .env
   ```

3. При необходимости измените в `.env` секретный ключ, параметры PostgreSQL и даты акции. Не добавляйте `.env` в Git.
4. Соберите и запустите приложение:

   ```bash
   docker compose up --build -d
   ```

5. Выполните миграции и создайте пользователя для админки:

   ```bash
   docker compose exec web python manage.py migrate
   docker compose exec web python manage.py createsuperuser
   ```

Приложение будет доступно по адресу <http://localhost:8000/>. Регистрация: <http://localhost:8000/accounts/register/>. Вход: <http://localhost:8000/accounts/login/>. Админка: <http://localhost:8000/admin/>.

Остановить контейнеры можно командой `docker compose down`. Данные PostgreSQL сохраняются в Docker volume `postgres_data`. Команда `docker compose down -v` удалит этот volume вместе с данными базы.

## Что реализовано

- Регистрация и вход пользователей на основе Django auth.
- Форма регистрации чека с серверной проверкой даты акции, минимальной суммы и уникальности связки ФН + ФД + ФП.
- Проверка обязательных полей и форматов в браузере; форма отправляется через `fetch`, ошибки и успешный ответ показываются на странице.
- Личный кабинет со списком чеков пользователя и пагинацией по 10 записей.
- Обновление статусов чеков в личном кабинете через API каждые 15 секунд без перезагрузки страницы.
- Админка для проверки чеков. При отклонении модератор обязан указать причину. Статус «Вы выиграли» модератор назначает вручную.
- `GET /api/receipts/` возвращает чеки только текущего пользователя; используется сессионная авторизация.
- Адаптивная верстка основных страниц.
- Тесты валидации формы, создания чека со статусом «На проверке», изоляции данных API и обязательности причины отказа.

## Настройки акции

В `.env` задаются `PROMO_START_DATE` и `PROMO_END_DATE` в формате `YYYY-MM-DD`. Обе даты включаются в период акции. Дата и время покупки вводятся так, как указаны в чеке; приложение не выполняет преобразование часового пояса, поскольку чек не содержит надёжной информации о регионе покупки. Для проверки попадания в период используются даты.

ФН, ФД и ФП хранятся раздельно и должны быть уникальны в комбинации. Повторная регистрация такой комбинации запрещается для всех пользователей. Причина отказа обязательна только для отклонённого чека.

## Дополнительные возможности

- Автоматическое обновление статуса чека без перезагрузки страницы.
- Отдельный статус «Вы выиграли», который модератор устанавливает вручную.
- Тесты для основных правил валидации и модерации.

Загрузка фото чека и заполнение формы из строки QR-кода не реализованы.

## Тесты

Запустить тесты приложения `receipts` в Docker:

```bash
docker compose exec web python manage.py test receipts
```

## Работа с ИИ

- Больше всего ИИ помог с фронтендом: вёрсткой страниц и CSS-стилями. Также он помогал разбирать требования и объяснять Django.
- Первый вариант оформления статуса «Вы выиграли» не совпал с макетом: вместо фиолетовой плашки с иконкой подарка там была золотая звезда. Несоответствие обнаружили при сравнении с Figma и исправили.
- При дополнительном времени доработал бы обработку одновременной отправки одинакового чека: база данных не позволит сохранить дубль, но приложение должно вернуть пользователю понятную ошибку вместо серверной ошибки.
